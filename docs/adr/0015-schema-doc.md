# ADR-0015 — `vcm schema doc` JSON Schema human-readable generator

**状态**: 待实施（v0.7.0）
**日期**: 2026-08-21
**作者**: mm7 / pi

## 背景

vcm 有两个 JSON Schema 文件（`skill.schema.json`, `state.schema.json`），
source of truth。这些 schema 是机器友好的，但**人看不下去**：
- 难懂 `required` + `additionalProperties: false` 互相约束
- 没例子
- 没用 `description` (虽然 schema 里已经写了)

CHARTER §9 「任何修改代码同步文档」— 但谁能一眼读 JSON Schema？

## 决策

新增 2 个 CLI 命令 + 1 个 server 端点：

```bash
vcm schema doc <path>                   # 输出到 stdout（默认）
vcm schema doc <path> --output path.md  # 写文件
vcm schema doc skill                    # 简写：生成 skills schema 文档
vcm schema doc state
```

Server 端：`/docs/schema/<name>.md`（v0.3 已有 `/docs/<path>`，扩展之）。

### 输出结构

```markdown
# Skill Manifest

> source: lib/schemas/skill.schema.json · generated by `vcm schema doc`

## Required fields

| name         | string  | pattern `^[a-z][a-z0-9-]*[a-z0-9]$` |
|--------------|---------|------------------------------------|
| description  | string  | 30–200 chars · skill-authoring §3 |
| tags         | string[]| minItems: 1, maxItems: 10         |

## Optional fields

### `authority`
- type: `string`
- enum: `["canonical", "execution-index"]`
- default: `"execution-index"`

### `canonical_ref`
- type: `string`
- required when `authority = execution-index`
...
```

### 反对意见

- **Q: 不用 TypeDoc / typedoc-markdown-plugin 之类?  
  **A: 那是 TypeScript 专用的。我们是 JSON Schema。
- **Q: 为什么不让用户自己 `python -m json_schema_docgen`?  
  **A: 包不存在。最简实现是 80 行 stdlib。

### 后果

#### 正面

- Schema 的 human reader 入口
- 与 `/docs/<path>` 集成（不需要新增 web 路由）

#### 负面 / 风险

- 增量 ~120 LOC + 30 LOC 测试
- 输出不是 canonical，破坏 diff 噪音（写 .md 但不提交）

### 验收

```bash
vcm schema doc skill | head -20     # markdown 表格 header
vcm schema doc state --output docs/STATE-SCHEMA.md
git diff --stat                      # 1 file changed
```

### 不做

- ❌ HTML 输出（v0.8.0 可加）
- ❌ Link-checker
- ❌ 自动 markdown diff PR check
